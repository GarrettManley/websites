mtga-companion is a local tracker for MTG Arena. It follows the log the game writes, keeps every entry in SQLite, rebuilds matches and game state from them, and answers questions through fifteen read-only MCP tools. A separate always-on-top overlay shows the match in progress.

The failure I designed against is a wrong number. Every rate carries its sample size and an interval, and below ten games a cell shows only wins and losses.

## Decisions and their limits

<DecisionRecords records={frontmatter.decisions} />

A correct view change once made three card tools 2.4 to 3.1 times slower with every test green; a manual timing run and bisect found it, and the guards catch only the shapes they seed.

<Disclosure summary="Show how query work is counted (Rust)">

```rust
pub fn count_vm_work<T>(&self, f: impl FnOnce() -> T) -> (T, u64) {
    let ticks = Arc::new(AtomicU64::new(0));
    let seen = Arc::clone(&ticks);
    self.conn.progress_handler(
        1,
        Some(move || {
            seen.fetch_add(1, Ordering::Relaxed);
            false
        }),
    );
    let out = f();
    self.conn.progress_handler(1, None::<fn() -> bool>);
    (out, ticks.load(Ordering::Relaxed))
}
```

## How it was built

I set the goals and anti-goals, accepted each sprint against machine-checkable criteria and ran the attended production migrations. From the first sprint on I required each task's test cases and mutations to be designed and reviewed before implementation. Claude Code agents wrote the code under an AI controller, and a second agent reviewed each task and re-ran the mutations. Three phases and seven sprints landed as 349 commits over ten working days between 2026-10-25 and 2026-11-12.

## What's next
