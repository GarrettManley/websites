    heldBy: "A test ingests a recorded session of 19,378 entries (62 MB of log text), exports it and requires the same SHA-256."
    limit: "One recorded session. Exact reproduction dates from schema version 3; earlier rows were backfilled."

    heldBy: "Two tests parse one recorded session (its first 6 matches, then all 25) in 64 KiB steps, with restarts partway, and compare a fingerprint of all 18 derived tables with a from-scratch rebuild."
    limit: "The restarts are simulated inside the test process, not real process restarts."
  - title: Query cost is counted by a test and timed by hand
    rejected: "A wall-clock threshold in the automated test run. Exempting follow-up fixes from re-timing."
    heldBy: "A test counts SQLite's virtual-machine work for the card tools on seeded stores and fails at 25% over a committed baseline; five query-plan tests; a timed comparison of parent against candidate before merge."
    limit: "The budget catches the data shapes it seeds: it later passed a second slowdown, of 1.5 to 2.3 times, until a second seed with a large card table was added. The timed comparison is manual."
  - title: The overlay holds the opponent's hidden cards only as counts
    rejected: "Using the opponent's available actions. Reading game memory."
    heldBy: "An allow-list of 37 snapshot key paths: a new field fails a test until the list file is edited. A second test strips the action list from every game-state message of a recorded 25-match session and requires identical derived tables."

The derived tables hold matches, games and game state. A parser fix is a version bump: the next parse empties the derived tables and replays every session in one transaction, and incremental parsing must leave exactly what that rebuild would.

## Decisions and their limits

A correct view change once made three card tools about three times slower with every test green; a manual timing run and a bisect found it. Record 03 is what came of it.

<Disclosure summary="Show how query work is counted (Rust)">

```rust
pub fn count_vm_work<T>(&self, f: impl FnOnce() -> T) -> (T, u64) {
    let ticks = Arc::new(AtomicU64::new(0));
    let seen = Arc::clone(&ticks);
    self.conn.progress_handler(
        1,
        Some(move || {
            seen.fetch_add(1, Ordering::Relaxed);
            false
        }),
    );
    let out = f();
    self.conn.progress_handler(1, None::<fn() -> bool>);
    (out, ticks.load(Ordering::Relaxed))
}
```

## How it was built

I set the goals and anti-goals, accepted sprints against machine-checkable criteria, with misses recorded as failures, and authorised the production migrations. The rule from the first sprint was that each task's test cases and mutations were designed and reviewed before implementation. Claude Code agents wrote the code under an AI controller, and second agents reviewed the tasks, re-running the mutations in most sprints. Three phases and seven sprints landed as 349 commits on ten days between <time datetime="2026-10-25">2026-10-25</time> and <time datetime="2026-11-12">2026-11-12</time>.
